# 先拆解，再按导航实现

制作 skill 的输入是已经完成的 TA 拆解与实现导航。参考图表达目标，拆解包解释目标；项目旧代码和旧资产只是复用候选，不得反过来覆盖这张参考图。

## 在调用制作 skill 之前

先形成可查看的拆解文档、图层清单/素材、坐标/Z/连接与支点、运动露底/补绘范围、静态重组证据。用户已经给了拆解包时直接读取，不重做一份凭印象的拆解。

本项目完整示例：`assets/blue-sky-train/ta-breakdown/2026-10-24-r01/index.html`。它的 manifest 包含 37 个可见像素裁片与 8 组补绘范围。原位像素一致只证明静态分配与对齐；隐藏背景、轮组圆周、叶簇重叠和无限延伸资源尚未完成。图中的一台机车、一节客车以及坐标，均以本次拆解为准，不能套用旧运行案例的列车数量/位置。

只有裸参考图时，先完成这个独立拆解阶段并保存可交接产物，再进入本 skill 的实现阶段；不要在尚未建立对象关系和缺口记录时直接改运行代码。必要准备由 agent 自行完成，不要求小白手动整理 JSON，也不把此顺序变成额外审批。

## 给模型的清晰入口

有现有拆解包时，可生成可浏览的导航和机器可读导航：

```sh
node .agents/skills/layered-wallpaper/scripts/build-navigation.mjs --breakdown assets/blue-sky-train/ta-breakdown/2026-10-24-r01 --out assets/blue-sky-train/ta-breakdown/2026-10-24-r01/navigation
```

`--out` 必须是新目录；保留旧导航时换修订目录。脚本检查 source/layers 哈希和路径，读取 manifest 的真实数据，生成 `index.html` 与 `implementation-navigation.json`。当前提供蓝天湖桥的代码复用候选；新场景需复核路线，不把候选当成已接入实现。

读取顺序：

1. 导航 JSON：目标、来源、读文件顺序、图层映射和阶段依赖。
2. 原 `manifest.json`：精确坐标、Z、父级、支点、alpha、缺失区域和每层限制。
3. 原拆解网页：构图、色板、遮挡、补绘可视化与原位对照。HTML 可能内嵌很多图像，模型不要直接吞整份 base64；先读清单，按需看页面/图片。
4. 导航指定的项目实现文件：只读当前步骤相关函数，核对候选资产是否符合本张图。

## 导航要说明什么

每个源图层都要映射到运行时分组/对象，列出原 PNG、位置/尺寸、Z、父级、支点、可见裁片状态、缺口、关联补绘范围、可参考的代码入口、候选资产及完成条件。37 个拆解裁片不必对应 37 个 draw call；合并刚体或拆分运行部件都须保留源层到运行对象的追踪。

实现阶段按依赖推进：静态 1:1 重组 → 补齐启用运动会露出的区域 → 世界位置与绑定 → 视差与独立时钟 → 岸水衔接/反射 → 完整工作台 → 适配后的验收导出。

静态 Z 与拆解父级是原位叠合/建议连接，不直接等于运行时骨架。没有完整轮周就不旋转轮片；云底、叶片接缝和画幅外未补齐时，不把裁片当作可无限循环的完整素材。缺口只阻止受影响的动作，静态重组、数据绑定和其他独立步骤仍可继续。

本图的水底片合绘天空/云山倒影；没有可独立确认的完整列车倒影。要做实时反射时需按新的明确反射源重建并去掉重复烘焙内容。旧案例的水位/镜轴不能直接当成本图的真值。

## 使用者给模型的话

> 先读取这份 TA 拆解文档及 implementation-navigation.json，再使用 $layered-wallpaper。把拆解结果作为本场景的依据，沿导航复用项目现有代码和合适资产，先补齐所启用动作的素材缺口，再实现完整工作台网页。不要套用旧图的坐标、车厢数量或把静态裁片当成完整运动素材。

实现记录逐项标明已完成、待补素材、已验证与未测，附真实文件和证据。导航文件本身是计划，不代表已实现动态壁纸。
