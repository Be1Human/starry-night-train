# 工作台网页交付规范

这是制作 skill 的必要交付要求。在本次 TA 拆解与实现导航就绪、已被读取后，复用这里的网页范本；页面结构不能替代拆解依据。范本为 `themes/blue-sky-train/lab/layered-stream/index.html`；`camera` 指定初始位置，`revision` 只是刷新标签，不是版本选择器；不要把 4178 端口当成必须存在的作者服务。

## 先读、复用，再调整

必须检查范本三件套及其真实依赖：

- `index.html`：页面区块、已有控件与 DOM ID。
- `style.css`：浅色工作台、分层侧栏、大幅预览、操作栏、卡片、窄屏布局及纯壁纸模式。
- `app.js`：四种视图、图层清单、素材缩略图/下载、方向/速度/暂停、世界坐标、时钟和宿主接口。
- `cases/blue-sky-layered/world.mjs`、`renderer.js` 与相关 Shader/素材处理模块：场景数据与实际绘制。

默认沿用这套 HTML/CSS 和交互骨架。新主题可派生相同目录层级的工作台与案例，按需改动场景数据和绘制；已有素材保持原路径引用。用户只需启动、打开网页、操作，不承担模块拼装、路径修复或环境迁移。

## 必须保留的页面结构与行为

1. **顶部信息**：当前主题名称、简短说明、真实加载/错误状态、回到起点、全屏预览。导航只指向目标项目内存在的页面；精简包不能链接到未随包提供的旧实验页。
2. **分组图层侧栏**：按远景、中景、列车、水面、近景等实际分组列出图层；可以开关显示、点击选中并独立查看、全部显示。名称、顺序、类型、数量和视差来自当前场景清单，不沿用旧主题的假数据。
3. **主预览**：大幅横向动态画面，按场景原始比例显示，不拉伸山体或素材；有清楚的加载/失败反馈。保持范本的空间、圆角、卡片和控制区组织方式，场景内容可以不同。
4. **四种真实视图**：动态组合显示完整运行场景；单层运行显示选中图层及其必要依赖；独立素材显示实际使用的处理后资产、透明底、尺寸与下载；原画参考显示当前主题的参考图。切换后选中状态和说明同步，不能只更换标签。
5. **播放与行进**：播放/暂停、车头左右换向、速度、前后一屏、回到起点；存在随机路段时保留下一段风景，存在独立云随机时保留换一组云。方向、暂停和参数真实影响画面。屏数、世界坐标、实例与帧数/耗时读取运行状态，不写演示数值。
6. **图层说明和设置**：展示当前图层名称、类型、用途、视差和查看/下载操作。程序图层没有位图时给出合理的禁用状态。水波、风和辅助标尺等设置随当前效果提供，不能留空壳按钮。复用已有音频时保留播放、音量、暂停联动与下载；没有音频不要求另行生成配乐。
7. **一致的预览与壁纸模式**：默认无参数 URL 显示完整工作台；`?wallpaper=1` 以同一份场景状态、素材和绘制逻辑显示纯壁纸。两套模式不分别实现动画。离线包和 `?controls=1` 的适配交给验收导出 skill。
8. **可用的窄屏布局**：沿用范本响应式规则，侧栏和卡片可重排，控件可触达且页面无横向溢出；用户能够从素材页和独立层回到组合视图。

具体 DOM ID 可参考现有 HTML 和 app 的调用。直接复用 `app.js` 时保留它依赖的元素与事件，不要只复制样式，留下查询失败或无响应的按钮。

## 新主题怎样最少改动

建议沿用 `themes/<theme-id>/lab/layered-stream/{index.html,style.css,app.js}` 与 `cases/<case-id>/` 的分工；派生案例时只复制需要调整的代码，稳定的逻辑可以直接共享。现有蓝天案例与原始资产保留。

由 agent 完成这些适配：

- 更改场景模块导入、参考图地址、标题、图层文案、可用效果和音乐信息；素材路径仍从清单解析。
- 将初始选中图层设置为当前清单中的有效项，图层和素材数量与实际数据一致；新增/删除图层不应留下旧按钮、说明或下载项。
- 保持 `ready/state`、`renderAt`、`pause`、`direction`、可见性、素材导出与 `stats` 等原有交互/验证能力，按新主题适配第二个 skill。
- 让启动命令打印并打开目标工作台的正确地址；新主题的启动/doctor/构建/验证适配一并完成，不让用户手改当前蓝天专用脚本。不得用蓝天页面或蓝天报告代替新主题的交付。
- 沿用已有 Node 服务、资源相对路径和本地音频，不因新增场景要求 npm 安装新框架、API Key、AI 模型或作者的绝对路径。

交付说明简要列出：沿用哪个工作台和案例、直接复用了哪些资产、哪些地方有必要适配、哪些资源确实缺少而新增。无需让小白逐个选择技术实现或手动接入已有组件。

## 完成判定与验收分工

完成制作后实际打开目标工作台，核对四种视图、任一图层开关与选择、素材下载、方向/速度/暂停/复位、原画地址和桌面/窄屏显示，保留网页截图。复制页面文件或出现一帧画面不代表工作台完成。

将目标入口、复用清单和网页行为要求交给 `wallpaper-quality-export`：由它运行适配后的正式功能验证、无损性能比较、HTML 报告与离线导出。制作 skill 维护这份网页要求，第二个 skill 维护测试与导出流程，避免双份脚本各自演变。
