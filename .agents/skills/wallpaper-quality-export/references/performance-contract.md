# 保持现有效果的性能验收契约

## 不可偷换的条件

相同素材与色板、相同画布/Shader 缓冲分辨率、相同图层与对象密度、相同世界单元规则/种子/可见区域、相同相机和时钟、相同波光/风/烟细节、相同采样/透明度与反射路径。样本图必须逐像素一致。

允许改变实现手段：准确缓存、不重复上传、批处理不影响混合顺序、复用 TypedArray/Canvas、静态预计算、移除证明无效的工作、保证不误剔除的范围检查。不允许通过拉伸纹理、减少对象、降低分辨率、减噪声次数、跳过动画绘制或调低实际帧率获益。

无损不是一句口号。查源码变更是否保持语义，运行固定帧与专项行为验证，并观看连续播放。在不同显卡/浏览器结果不同的情况下先复现，不能把像素容差自动调大直到通过。

## 指标读法与边界

- `renderMs`：JS 与 Canvas 绘制命令提交时间，包括当前实现同步等待的部分；不等于总 GPU 耗时或 CPU 占用率。
- 实际绘制帧间隔：只在播放器 frames 增加时采样 rAF 时间；与 CPU 时间分开，报告平均 fps 与较慢的 P95。暂停和单帧 renderAt 不能代替真实播放。
- GPU pass：岸线与蒸汽的 EXT_disjoint_timer_query_webgl2 最近完成读数。异步结果可能重复；不是独立整帧样本，也不能相加当总 GPU。
- textureBytes：当前案例已统计素材/部分缓存的 RGBA 估算，不包含全部 Canvas、驱动副本和合成器资源。不是完整显存占用。
- 首屏截图与 HTML 包尺寸：不是流畅度指标。
- headless 浏览器：可重复自动测试；不是 Wallpaper Engine 原生宿主。软件渲染器会阻止默认性能通过，需用实际目标硬件复测。

当前默认 60 fps：帧预算 16.67 ms；各组 CPU 提交 P95 ≤ 80% 预算，平均 fps ≥ 90% 目标，帧间隔 P95 ≤ 1.6 倍预算。阈值是项目验收选择，不是工业标准；修改目标必须在基线和候选上保持一致，并说明原因。不得优化失败后偷偷改目标。

报告覆盖六组短时采样（3 镜头 × 2 轮），每组先预热 20 帧再取 90 帧；`--samples` 可调 30..240。低于 30 不接受。更严格验收应增加连续播放、多硬件/窄屏/长时间/宿主复测；不可把已有短测夸大成全部平台保证。

## 优化与证据循环

1. 新目录保存原版截图、哈希、环境、采样配置、原始结果。
2. 定位一个瓶颈，写清工作为何可以复用或省去及缓存失效条件。
3. 保存当前源文件状态，仅修改授权范围；不要碰素材或调整视觉来对齐结果。
4. 同条件对照，任何固定帧或契约变化先判失败。检查缓存切换、隐藏/恢复、双向、千万坐标、小山遮挡和水沿边界。
5. 对比 CPU 平均与 P95、播放帧间隔，不挑最好镜头；源码相同的波动不算优化。
6. 无可靠收益则保留原实现或只撤回本轮变更；失败报告仍要可读。性能达标且无瓶颈时不强行修改。
7. 源码/素材在测量、专项、构建后必须仍匹配同一版本。通过以后输出包和 checksum。
