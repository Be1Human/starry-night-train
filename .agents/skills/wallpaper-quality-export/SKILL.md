# 壁纸验收、无损性能优化与导出

功能正常、画面保持、性能可测，才能交付。以用户当前认可的画面为准；不通过降低画质完成性能任务。所有证据和包留在所属项目内。

## 1. 确认范围并建立基线

读项目 AGENTS、当前入口与 [验收/导出地图](references/checks-and-export.md)。先运行 `npm run wallpaper:doctor`。本仓库脚本需要 Node.js 22+ 和 Chrome/Edge，自动寻找本机浏览器；可用 `EDGE_PATH` / `CHROME_PATH` 指定。不要静默下载浏览器、改显卡设置或安装全局工具。

在任何优化改动**之前**运行：

```sh
npm run wallpaper:audit -- --out docs/verification/my-baseline
```

输出目录必须是新目录，保留基线不覆盖。先读 `report.html`，按需查看 `audit.json` 和固定帧。基线因性能不达标返回非零仍可用于比较；执行错误或缺图的基线不能使用。

当前适配器测三个镜头、每镜头两轮真实播放；固定帧覆盖开阔/林坡/小山、换向、远距离、另一种子及云/烟/水/枝叶独立层。内部 2048×768、显示窗口 1920×1080；不能声称是原生 4K 性能。更换主题前按参考文档适配，不能拿蓝天报告为其他壁纸验收。

## 2. 定位瓶颈，再做保持效果的优化

读 [性能与效果契约](references/performance-contract.md)。分别分析 CPU 提交、真实帧间隔、已提供的岸线/烟 pass GPU 读数和素材缓存估算；缺失指标写“未测”。需要时增加有范围、可移除的计时点定位重复工作，不把计时/像素读回的开销计入候选的正常运行。

优先处理重复计算、重复上传、准确缓存与失效、热路径分配、离屏剔除和资源生命周期。保持相同素材、分辨率、图层、植物密度、世界分布、时间、随机种子、采样与着色结果。不要减少噪声层数、水波、倒影、云细节或风摆；不要自动降质量。

一次改动解决一个可测量问题，记录具体原因与预期收益。没有瓶颈或没有可证收益时保留当前实现，报告“已达门槛/未证明优化收益”，不要为了交付虚构优化。需要改视觉才能达标时如实报告未达标，不能偷偷放宽门槛或修改基线。

## 3. 用同条件验收候选

```sh
npm run wallpaper:audit -- --baseline docs/verification/my-baseline --out docs/verification/my-candidate
```

对照要求同浏览器/显卡、采样配置、固定镜头和时钟；固定帧逐像素哈希一致，素材/世界/关键缓冲契约一致，动画、换向、暂停与往返继续正常。对照环境不一致时复测，不能自动提高误差容忍度。截图样本一致不证明所有状态数学等价，还须观看连续播放、方向切换与遮挡边界。

源码没改时，帧时波动不能叫优化。修改后平均提交时间至少改善 5% 且 P95 不变差，才标为样本收益；存在波动时增加复测，别挑最好的一次。GPU 总帧耗时、系统功耗/占用与原生宿主没测就保留“未测”。

失败则保留证据、定位并修复；必要时只撤回自己本轮的优化，不碰用户未提交改动、不做 hard reset。不得导出未通过候选作为正式交付。

## 4. 专项检查、断网导出与 HTML 报告

默认完整交付：

```sh
npm run wallpaper:verify-export -- --baseline docs/verification/my-baseline --out dist/my-release
```

命令默认 `--area all`，执行所有蓝天案例专项测试；每项单独保存证据，然后在候选目录构建，断网打开 `file://` 版本检查素材、Shader、音乐与宿主暂停。通过后才将候选标记为 `package/`。优化前后不匹配、性能失败或专项失败会阻止交付。

没有优化、只交付当前版本时可以省略 `--baseline`；报告应明确“当前基线，未证明优化收益”。`--area` 可按改动选择复查范围，但完整交付优先用 all，别把部分测试说成全部验收。输出的 `project.json`、单文件 `index.html`、`preview.png` 可导入 Wallpaper Engine；实际原生宿主与听感仍由目标电脑检查。

报告由 `scripts/report.mjs` 生成，无 CDN、无需服务、可双击阅读。用结论、实际画面、每帧预算、白话指标、逐项结果和下一步帮助小白理解；失败也必须保留报告与日志。只有基线时不显示虚构的“优化前后收益”。

最后给出报告路径、已通过/未测范围、是否改变源码以及 package 路径。详细数据在 audit.json，避免向用户堆原始测量 JSON。
