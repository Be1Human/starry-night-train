# 分层动态壁纸制作

先完成拆解，再把拆解文档和本 skill 一起交给模型，沿实现导航把画面变成动态世界。以本次拆解为场景依据，以项目旧代码和合适资产为复用参考，交付完整工作台网页。

## 前置输入：拆解文档与实现导航

先读 [拆解到实现的交接规范](references/breakdown-first.md)。必须先有可查看的 TA 拆解、原图/图层清单、坐标/Z/连接、缺口和静态对照证据，再进入实现。用户已给拆解文档时直接读取并补齐实现导航，不回到“只看参考图套旧案例”的流程。

优先读 `implementation-navigation.json` 与 `manifest.json`，再按需查看原 HTML/图片和导航指向的代码入口。导航把每个源图层连接到运行对象、待补资源、复用函数、依赖顺序和完成标准；内嵌大量图像的 HTML 不宜整份读取 base64。需要时用 `scripts/build-navigation.mjs` 从现有清单生成导航，数据必须再按当前需求复核。

只有裸图时先完成独立的拆解准备，再进入本 skill 的实施阶段；agent 自行完成交接整理，不让小白手工编清单。静态像素一致不代表素材可独立运动。按已启用的动作先修复隐藏背景、接缝、部件与画幅外缺口；缺口只约束受影响动作，不阻止其他独立工作。

## 必须交付的网页

以 `themes/blue-sky-train/lab/layered-stream/index.html` 为页面范本，必须先读 [工作台网页交付规范](references/workbench-contract.md)。默认入口应保留现有页面布局与交互：顶部标题和状态、分组图层侧栏、主预览、四种视图、播放控制、图层详情和设置区。所有按钮、图层开关和素材下载都接入真实场景。

新场景沿用这套工作台，只替换场景数据、原画、文案与必要的实现；`?wallpaper=1` 提供同一场景的纯壁纸模式。单独的动画画布、截图、视频、只有说明的页面或纯壁纸视图，均不满足本 skill 的网页交付要求。技术验收和离线包由第二个 skill 负责，不能代替这份可操作网页。

## 先运行，再改动

1. 确认目标项目，读其 `AGENTS.md`。本 skill 位于项目的 `.agents/skills/`，所有路径都相对该项目；不要依赖作者电脑上的素材、服务、模型或全局 skill。
2. 读取本次拆解和导航，记下原图哈希、对象数量、坐标、父级和未补齐的区域，再运行 `npm run wallpaper:doctor` 与 `npm run wallpaper:start` 核对旧案例的可复用能力。旧网页能运行不代表新图已实现。
3. 阅读 [项目参考地图](references/project-map.md)，按导航读范本的 `index.html`、`style.css`、`app.js` 和案例相关函数，确认可复用的网页、时钟、素材处理与 Shader。旧案例源码有自己的权威源，但本场景的构图和资产状态以新拆解为准；不能复制旧图的坐标或车厢数量。
4. 用户要新主题时，从现有工作台和案例派生独立主题，按交付规范调整导入、入口和清单，保留蓝天示例；修复当前主题时原地修改权威源。启动命令必须打开目标工作台，不能让小白手工改端口、导入路径或找到另一个主题才看得到结果。

## 复用优先

在拆解导航约束下，按「现有工作台与算法 → 与本图相符的完整资产 → 必要适配与补绘」选择实现。先检查 MATERIALS、图集区域、素材处理代码与提示词记录；匹配画风、造型、尺度与锚点后才引用已有资产。已有代码可复用不等于旧图所有素材都可直接替换本图。

只对实际不适用的部分进行裁切、调色或逻辑调整，派生资源另存并保留来源。只有现有资源无法满足目标时才生成新素材或重写对应模块，并说明具体缺口。沿用 Node 本地启动、现有样式和交互，不为复现工作台另建框架、引入打包链或要求用户配置在线服务。必要适配由 agent 完成。

## 制作流程

### 1. 按拆解重组，落实动静关系

先按 manifest 的原坐标、scale=1 和 Z 静态叠合，核对拆解的源图和证据。再按导航落实每层的运行对象、父级、接地锚点、运动来源、遮挡和反射依赖。不得把静态 Z 直接当运行骨架，也不凭旧模板覆盖本图关系。

本例镜头跟随列车：列车相对屏幕近乎静止，景物随世界位移经过；越近位移越快。烟、水波、云风和枝叶还有独立时间变化。列车换向时翻转整列车和烟囱位置，不只翻转车头。

用户说“不同风格”但上下文指不同场景时，保持同一画风，改变地形、空间和组合。用户已授权的素材路线和画面选择继续沿用，不反复询问。

### 2. 按缺口清单准备完整运动素材

按已选动作和 repair 范围补齐露底、连通裁片重叠边、轮组完整结构及循环边界，再启用对应运动。大幅改变构图或补画时先看整体预览；需要生成/编辑位图时使用可用的 imagegen skill 与工具。缺少生图能力时如实标明受影响的动作，不把几何占位或局部裁片当完整资源。

按 [素材与实现约定](references/implementation.md) 准备完整透明资产：完整山脊、树冠、树根和干净 alpha；桥梁使用可接续单元；不要从一张整图切几条矩形就当作可无限延伸的世界。保存来源、提示词、原件、派生规则和哈希。

### 3. 固定世界与分层运动

用 `world.mjs` 的图层/素材清单和确定性世界单元组织场景。用世界坐标、种子和单元 ID 决定地形与植株，允许开阔段、林坡段和小山遮挡段随机交替。换向或往返不重新随机；只枚举画面及保护区内的单元，考虑素材真实边界，避免突然出现/消失。

摄影机位移与动画时钟分离：速度为零时烟和水仍可活动；暂停、宿主暂停及页面隐藏时冻结相应时钟；恢复不跳时间。山坡与山脚树丛共享世界相位。有限原画仍会复用，不能承诺无限独特绘画。

### 4. 按真实依赖合成

从天空、云、远山、中景林坡，到桥、列车、轨前小山、草岸、湖面、近景组织绘制。参考 `renderer.js` 的实际调用顺序与反射源，不只看列表顺序。

小山保持不透明核心，遮住桥和列车；不能用整体透明度淡化来“融合”。山体保持等比，不能横纵分别拉伸、逐列扭曲山脊。近景植株用多种真实轮廓、疏密群落、独立姿态和轻微风摆减少重复，不重新引入已移除的旧尖叶草。

岸线在世界坐标中生成宽窄、浅湾和凸岸，与湖面共用遮罩。用真实山脚接触纹理和局部高度/笔触混合，让树根接入草岸，保留山体轮廓。倒影从明确的反射源取得，与对象共享时间和姿态，经过水波与柔化；别把整个上半屏机械翻转。本例蓝色远山不进入湖面是构图选择，不是所有湖景的物理规则。

### 5. 交给独立验收与导出

制作 skill 负责实现，不维护另一份验收/导出流程。改动前后按 [wallpaper-quality-export](../wallpaper-quality-export/SKILL.md) 保存基线、运行相关检查、核对实际画面、生成 HTML 性能报告并导出。不要用低分辨率、删图层、减少植物/水波/噪声细节冒充无损优化。

实现记录保留“源图层 → 运行对象 → 实际文件 → 验证证据”的映射，区分计划、待补素材与已完成项。交付一条启动命令、目标工作台 URL、纯壁纸入口、复用与新增内容及验收报告和包；不能用旧案例画面或导航计划冒充新图完成。按网页规范核对交互并留截图。
