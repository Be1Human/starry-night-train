# 从参考图到自己的动态壁纸

这个仓库把列车壁纸的实现拆成可阅读、可预览的方法模板。你可以比较同一图层的不同做法，再挑选适合自己画面的方案。模板带有源码、参数和限制；它们的坐标、依赖与宿主不同，组合时仍需要适配，不能把任何两个模板直接互换。

公开[画廊](../library/index.html)分为「火车壁纸」和「分类素材」，只展示精选内容。完整场景归入壁纸，银河等单个图层归入素材；已有完整壁纸的素材提供案例跳转；独立成熟的素材也可以先收录。本文及 `modules/catalog.internal.json` 属于开发资料，包含尚未达到产品质量的历史方法，不作为素材推荐目录。

## 从 Gallery 交给 AI

先按视觉类别挑选效果，再打开「使用与源码」，复制 AI 使用说明，填写自己的目标与项目技术栈。AI 可以沿素材清单找到代码、透明 PNG、运行时、坐标/透明度约定与编辑入口。实现手段按效果选择：纯 Shader、素材驱动或混合实现都可以；替换一张好的云 PNG 往往比重写云算法更合适。

每项精选素材在 library/materials/ 中有同名 Markdown 说明与 JSON 清单。原星河提取代码依赖原宿主；蓝天混合方案依赖素材纹理和运行时。让 AI 先复制可运行预览验证，再移植到目标项目。清单帮助找到真实接口，不表示不同引擎无需适配。

素材与完整作品分别验收。某张壁纸整体还在完善，不妨碍其中已验证的桥、云或近景作为素材被复用。

## 目录如何阅读

```text
modules/<category>/<template>/
├── template.json        方法说明、来源、依赖与预览入口
├── module.glsl          模块实现，也可能拆为数个源码文件
├── README.md            原理、参数、适用范围与已知问题
└── preview.html         该方法的预览或来源预览入口
cases/<case>/
└── scene.json           完整案例使用的方法、素材与组合关系
library/index.html      完整壁纸与分类素材的精选画廊
```

`modules/` 回答“这个效果怎么实现”，`cases/` 回答“这些方法怎样组合成一张画面”。素材继续放在 `assets/`，历史版本、测试与录制证据保存在所属主题中。先查看模板状态：独立案例、主题内方法和历史实验的完成程度不同。预览入口能打开，不等于该方法已经被封装成通用组件。

## 1. 先确定完整画面与运动范围

先选一张构图满意的参考图，记录画幅、地平线、桥面高度、列车的宽高占比、主要云团位置和光线方向。先锁住这些比例，再调整细节。否则把火车缩小、把山抬高之后，云量、视差速度和倒影都可能需要重做。

例如蓝天湖景的原画是 2048 × 768，实验中将列车宽度校准到约画面宽度的 15%，高度约画面高度的 3.6%。这些是该案例的构图选择，不是所有列车壁纸的统一标准。

写清楚镜头要做什么：

- 画面基本固定，只让烟、水、枝叶轻动。
- 列车相对屏幕稳定，远山慢移、近景快速掠过。
- 镜头持续经过新的景物。

移动范围越大，需要补出的隐藏区域、完整素材与续接处理越多。做一段短循环与做无限行进场景，是不同的制作规格。

## 2. 按视觉职责拆图层

先用草稿列出图层，不急着把每一层都重画。

| 图层 | 要决定什么 | 本仓库可以参考的方法 |
| --- | --- | --- |
| 天空 | 色彩、明暗中心、星点与银河 | 蓝天渐变；星河噪声光带与闪星 |
| 云 | 固定构图还是持续出现新布局 | SDF 积云；球冠簇；四层平涂遮罩；完整透明云素材流 |
| 山与远岸 | 轮廓、空气透视、距离与移动速度 | 多层噪声山脊；周期山峰包络；夜间远岸灯光 |
| 桥与轨道 | 比例、桥孔、材质、局部受光 | 简化石拱桥；蓝灰石桥；独立前层护栏 |
| 列车与烟 | 车身坐标、轮轴相位、烟的出生位置 | 蓝天与星河 SDF 列车；世界空间烟团；连续烟带 |
| 湖面 | 水线、反射对象、波纹与染色 | 同场景重新求值的反射；完整原画局部 SVG 水波 |
| 近景 | 遮挡范围、经过频率、风摆 | 程序剪影；程序草叶实验；生成透明草丛与枝叶 |

湖面通常复用上方场景的求值结果，不需要把桥、列车和云再写一份。护栏在列车前、桥体在列车后，这类遮挡关系应写进案例，而不是根据文件名随意排序。

## 3. 为每层选一种合适的方法

先读模板的来源、依赖和已知问题，再打开最小预览。选型看目标风格与运动需求：

- 想保留参考图的平面色块关系，可以研究 R03 四层遮罩。它复用了参考 SVG 轮廓，原图遮挡区域和画幅外区域没有重建，适合有限移动。
- 想持续行进并保持已经画好的云形，可以研究 R04 完整 PNG 素材流。它能持续重新排列有限素材，不能生成无限种原创云纹。
- 想研究不依赖图像轮廓的程序云，可以比较 R01 椭圆 SDF、R02 球冠簇与星河云方法。它们各有外观和计算成本，不能假定加大噪声细节就会接近任何参考图。
- 想尽快让整张插画轻微动起来，可以研究正式蓝天入口的 SVG 局部水波与蒸汽，接受主体保持原构图这一限制。

同一场景可以混合程序图形和图像素材，但要为它们约定共同的色板与光照。先少选几种成熟做法，等案例跑通后再增加变化。

## 4. 组合前对齐接口

下面是组合时需要明确的约定，不表示每个现有模板已经实现了同一个 API。以各模板源码和 `template.json` 的真实接口为准。

| 约定 | 必须核对的内容 |
| --- | --- |
| 坐标 | 原点、Y 轴方向、单位、画幅、地平线、局部坐标到世界坐标的转换 |
| 时间 | 秒还是帧、暂停行为、倍速、能否按指定时刻确定性重绘 |
| 位移 | 行进距离由速度积分还是直接时间乘速度；近远层各自倍率 |
| 色与透明度 | 返回值是直通 alpha 还是预乘 alpha；合成函数必须匹配 |
| 光线 | 高光来自哪一侧，素材是否允许镜像，日光参数是否真的影响该层 |
| 依赖 | 噪声纹理、辅助函数、GLSL 宏、全局变量、宿主 DOM 与资源加载 |
| 输出 | 输出 RGBA 图层、RGB 整景，还是通过额外变量累加光晕 |

蓝天实验使用“画面高度为 1、+X 向右、+Y 向上”的世界坐标。整张 PNG 的 UV 通常需要翻转 Y 轴；图片尺寸应通过宽高比换算，避免云或树被横向压扁。

蓝天的 `over(back, front)` 按直通 alpha 合成，`front.rgb` 应为未乘透明度的颜色。某些内部累计过程会临时使用预乘值，返回时需要按约定还原。不能把已经乘过 alpha 的颜色再乘一次，否则透明边缘会发暗。

星河的部分图层通过 `gGlow` 累加光晕，而不是仅靠返回 RGBA。提取时要把这条输出路径一并处理。GLSL 宏也属于依赖：原云有 `CLD / BAND`，列车有 `PAINT`，场景合成有 `ADD`。

## 5. 先验证最小预览

对每个准备使用的模板，先在简单背景中检查：

1. 固定时刻的轮廓、分色与透明边缘是否符合目标。
2. 时间推进时有没有图案跳变、接缝、被裁掉的顶部或尾部。
3. 暂停、停止前进、改变风速是否各自符合预期。
4. 放进目标画幅后，细节是否还可见，计算量是否可接受。

只有整张素材完整可见时，才容易发现被背景藏住的边界、残色和拉伸问题。图像预览中透明像素的 RGB 可能看起来有底色；应以 alpha 数据和实际合成结果确认，不只凭单个预览工具判断。

## 6. 用案例记录组合关系

在 `cases/<case>/scene.json` 记录实际使用的模板、素材与组合配置，具体字段遵循仓库现有案例。案例说明还应能回答：哪些图层共用镜头，谁挡住谁，烟囱出生点在哪里，哪些层进入倒影，以及调速如何影响它们。

复用已有案例时，先换色板或完整素材，观察构图是否成立，再改几何与运动。蓝天主题和星河主题的机车方向、单位与烟囱位置不同；更换列车或烟时，需要坐标适配，不能只换函数名。

R10 已存在从星河提取原始连续烟带并接入蓝天的适配源码，但当前对应证据目录只有变更记录，没有完成的验证报告。可以学习它的适配方式，不应把它当作已验收结果。

## 7. 录制前验证组合

先观察实际播放，再捕获固定时刻做对照。重点检查列车尺度、烟从烟囱发出的位置、轮轴与行进关系、近景遮挡、倒影对齐和离屏续接。测试报告说明的范围要与结论一致：时间跳到 24 小时，可以检查该时刻重建与数值状态，不能证明连续稳定运行了 24 小时。

宣传片需要稳定的时间步进。星河现有录制工具使用固定时间步的逐帧渲染，再交给 ffmpeg 编码；实际性能检查则仍需真实播放。两种证据解决不同问题：逐帧导出保证视频帧序列完整，不能代替实时帧率验收。

完成后保存所用模板版本、素材、参数、固定时刻截图和短片。遇到问题时记录“触发条件—画面表现—原因—处理方法”，让下一个使用者能沿着证据继续改。

## 来源与复用范围

逐项阅读模板来源，不能因为代码放在同一仓库就默认具有相同许可。星河原版云算法来自 mdb，上游没有附带再分发许可；本项目保留“仅供学习与欣赏，请勿商用”的声明。详见[星河主题来源说明](../themes/starry-night-train/README.md#来源与许可)。生成素材的提示词和版本保存在对应 `assets/` 目录，也应随案例保留。
