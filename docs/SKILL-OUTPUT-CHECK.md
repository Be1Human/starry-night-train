# Skill 产物格式的实际使用检查

**简体中文** | [English](SKILL-OUTPUT-CHECK.en.md)

结论：当前蓝天示例的工程格式可以独立使用；这次修复了轻量包中的 6 处断链，以及首页自动跳回工作台、不方便找到说明的问题。新主题采用独立目录和启动适配器也能运行，但仍需由 AI 按新主题完成适配，不能把 starter 当作任意主题的自动生成器。

## 怎样检查的

在 Windows、Node.js 24 和本机 Edge 上实际生成 ZIP，再使用 Python 的 ZIP 解码器检查 CRC 和文件哈希，解压到含中文、空格的新目录运行。另用相同蓝天素材创建了 output-format-check 测试主题，保留原案例，分别检查工作台和离线 HTML。

- 轻量包共 203 个文件，解压后的文件与打包清单一致。
- 轻量包内 109 个本地文档和网页引用均可找到；加入第二主题的测试副本为 115 个引用，均通过。
- 首页的 9 个链接返回正常，工作台可返回首页继续找到说明。
- 四种视图、图层开关、实际 PNG 素材下载、播放/暂停和左右换向通过。
- 1440×1000 桌面和 390×844 窄屏检查通过；窄屏没有横向溢出。
- 第二主题的目标命令启动了自己的主题入口和场景模块，原蓝天源码保持原样。
- 新目录内成功构建离线网页；断网的 file:// 播放、17 个素材、内嵌音乐、宿主暂停与换向接口通过。
- 原蓝天、第二主题适配和离线网页在相同镜头/时刻输出的固定画面完全一致；岸线和烟的 WebGL 错误均为 0。

## 修复内容

轻量包现在带可返回的首页、当前工程说明、正确的来源声明和所引用的星空原始单文件。精简包中的文档改为指向实际提供的文件，不再依赖未附带的历史报告或旧实验页面；作者的拆解制作环境不会被整个复制进包里。

两份 Skill 同时明确：回复给用户本机实际绝对路径；随 ZIP 分发的说明保留相对工程根的路径和启动命令。端口以终端当次输出为准，换电脑或换解压目录后仍能照着使用。

## 如何复查

在完整项目根目录运行 npm test，会检查世界/云布局，以及实际生成的 starter 包的链接、ZIP 内容、文件哈希和启动准备状态。也可运行：

```sh
node tools/check-project-links.mjs 需要检查的工程目录
```

这次验证的是工程格式、可迁移性、当前案例的派生与浏览器使用流程；第二主题复用了蓝天内容，没有把它当作另一张新原画的实现成果。未测试任意新图的自动拆解/补绘质量、原生 Wallpaper Engine 运行、实际创意工坊发布、听感或 4K 性能。
